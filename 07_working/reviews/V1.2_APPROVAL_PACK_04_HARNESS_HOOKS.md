## 官方 Codex Hooks 能力核验

核验日期：`2026-09-01`。

- OpenAI 官方 Hooks 文档确认 Codex 原生支持 `SessionStart`、`PreToolUse`、`Stop`、`SessionEnd` 等当前 Registry 使用的事件。
- Project Hook 可来自 `.codex/hooks.json` 或 `.codex/config.toml`；Project 本地 Hook 只在项目配置层受信任时加载。
- 非托管 Hook 必须按当前定义 Hash 完成 Review/Trust；定义变化后必须重新确认。
- 同一事件的多个 Command Hook 会并发启动，Hook 之间不能假设串行阻止。
- `PreToolUse` 可阻止受支持的本地工具路径，但官方文档明确部分特殊工具路径可绕过默认 Hook 路径，因此 Hook 是 Guardrail，不是完整权限或安全边界。
- Official Evidence：<https://learn.chatgpt.com/docs/hooks>。

## 初审结论

Harness 已具备可运行的最小闭环，过去对 Factory、Schema、Recovery、Tag 与 GC 的加固也有测试支持；但当前文档、配置和实现之间仍存在会影响 V1.2 Stable 的确定性差距。建议完成以下七组修正后整包批准。

## 批准前必须修正

### 1. Release Gate Config 必须成为真实配置源

- `release_audit.py` 必须加载并验证 `release_gates.toml` 的稳定 Schema、版本、Gate 顺序、ID 与名称；配置漂移或缺失应 Fail Closed。
- 移除当前 `[promotion] requires = "M6"` 与 M6 又要求 annotated tag 的循环表达。Promotion/Release Activation 继续由 Governance 和 Founder 授权，不伪装成第七个 Gate。
- `release_gates.toml` 固化稳定版本、`APPROVED` 状态和 Pack Approval Reference。

### 2. M2 必须代表完整且无递归的本地验证

- `ci_gate.py` 与 M2 共享同一组可复用本地检查定义；Release Audit 不能只运行 Repository Validator。
- 避免 `release_audit → ci_gate → test_release_audit → release_audit` 递归：M2 运行除自身 Release Audit 测试外的全部基础检查，外层 CI 单独运行 Release Audit 测试。
- M2 Evidence 必须列出实际执行的 Check ID 和结果，不能只返回最后一行 `ERRORS=0`。

### 3. M3 改为当前 Pack 的真实 Apply E2E

- 对每个 Approved `PROJECT_SCAFFOLD` Pack 在临时目录执行 `--apply --git`，验证 `.paos-init.json` V0.2、Pack Digest、Template Approval Reference、`PROVISIONAL` 状态、逐文件 Hash 与 Git main。
- 不再把历史 `07_working/reviews/PROJECT_FACTORY_ACCEPTANCE.md` 的 PASS 字面量作为 Gate 依赖；Repository Validator 也不得要求历史 Working Review 才能运行。
- Repository Validator 必须核对 `factory.toml` 中 Approved Pack Digest 的完整覆盖、精确匹配及无多余登记，并拒绝 Pack 内 symlink/特殊文件。

### 4. Schema 与 Repository Validator Fail-Closed 加固

- 将 Schema Pack 固化为 Approved Contract；核心对象补齐已实际使用字段，并在安全可行处使用 `additionalProperties = false`，避免拼写错误静默通过。
- `SYSTEM.target_version` 改为可持续 SemVer 约束，不继续硬编码只到 `1.1.4`。
- `uniqueItems` 使用稳定的结构化规范化，不依赖 Python `repr`；非法正则或错误关键字类型应作为验证错误返回，不导致 Validator 崩溃。
- Canonical 验证范围排除 `99_temp/quarantine`、受管 GC Plan 和 Archive 的历史格式；这些区域不是当前配置源。Secret/路径安全扫描可按独立策略保留必要覆盖。
- Required Files 只保留当前运行入口与 Canonical Contract，不依赖旧 Working Review。

### 5. Tree Digest、M5 与 M6 证据精度

- Tree Digest 升级为版本化算法，纳入 Git path、mode、object kind 与 blob SHA-256；Working Tree 和 Commit Evidence 使用同一算法，避免普通文件与 symlink/执行位变化得到相同 Digest。
- M5 保留固定 Bundle 路径、Bundle SHA、`git bundle verify`、Head 与 Commit Tree 校验；Pack 04 只验证证据，Pack 05 负责生成与恢复。
- M6 除 Approval Reference 外还必须验证 annotated tag message 中的版本；所有缺失/解析错误转为明确 Gate `FAIL/BLOCKED`，不得抛出未处理异常。

### 6. GC Plan 授权、路径与 Retention 闭环

- `plan_id` 必须使用固定格式，并与受管 Plan 文件名一致；Quarantine 目标必须再次做真实路径 containment 校验，拒绝 `../` 等逃逸。
- Apply 必须接收并记录 Founder 单次授权引用；`gc.toml.require_founder_approval = true` 不能只存在于配置而不被执行器消费。
- 按已批准 Retention 计算候选年龄；`99_temp/` 任意项必须有真实引用扫描证据，不能仅写固定字符串声称已扫描。
- 拒绝候选目录中的嵌套 symlink/特殊文件；Applied Record 增加原路径、权限模式、移动后 Hash、恢复截止日和授权引用。
- 继续只允许可恢复 Quarantine，不加入永久 Delete。

### 7. Hooks 只批准边界，不批准虚构实现

- 将 `HOOKS.md` 从“候选边界”修正为 Approved Implementation Boundary，并明确当前实现数量为 0、默认禁用。
- `hook-registry.schema.json` 增加适用平台、实现状态与 Runtime Evidence 字段；不同平台事件语义不得因名称相同而视为同一实现。
- 当前 `02_registry/hooks.toml` 保持 Working/Disabled；`pre-tool-safety-check` 的 `blocking`、side effect 与 failure policy 在实现前必须一致，不能同时声称可 Deny 又标记 non-blocking。
- Hook 不得替代 Codex Sandbox/Approval、PAOS Governance 或平台权限；官方声明未覆盖的工具路径一律不得宣称已阻止。
- 本 Pack 不生成 `.codex/hooks.json`，不执行 Trust，不启用 Hook，不采集 Conversation/Secret，也不新增外部传输。

## 风险与回滚

- 风险：M2/M3 变严格会暴露现有隐藏失败；这是 Gate 真实性修正，不应通过降低检查范围解决。
- 风险：Tree Digest V0.2 会使旧 Recovery Digest 只作为历史 V0.1 Evidence；V1.2 必须生成新恢复证据，不改写 V1.1.4 记录。
- 风险：Retention 生效后，新产生 Cache 可能不立即进入 Quarantine；计划应准确记录“尚未到期”，而不是绕过已批准保留期。
- 风险：关闭 Schema 未知字段会揭示当前隐式字段；应先补齐正式 Schema 再启用 Fail Closed。
- 回滚：独立 Implementation Commit；失败时 Git revert，不移动 `v1.1.4` Tag，不触碰 Quarantine 中既有恢复资产。

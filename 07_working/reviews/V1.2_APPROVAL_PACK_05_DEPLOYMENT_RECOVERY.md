## 批准前必须修正

### 1. 修正官方配置漂移与 Trust 语义

- Gemini Profile 将 `loadFromIncludeDirectories` 更正为当前官方 `loadMemoryFromIncludeDirectories`，重新生成并部署项目配置。
- Codex/Claude/Gemini 文档明确 Project Trust、Settings Load、Context Load 与 Live Runtime 是不同证据层，不再仅以“文件存在”宣称配置生效。
- 只使用平台当前官方 Schema/自检验证原生配置；不得在 Generated 文件中发明跨平台通用字段。

### 2. 刷新时间敏感 Capability/Runtime Evidence

- 将本机观察版本刷新为 Codex `0.152.0`、Claude Code `2.1.252`；Gemini 保持 Not Installed。
- 每条 Runtime/Capability Evidence 记录 `observed_at`/`verified_on`、证据来源与精确状态；缺少版本或证据的记录 Fail Closed。
- Configured、Deployed、Config Loaded、Context Loaded、Runtime Verified 与 External Data Authorized 必须分别记录；不因本地 CI 通过推断 Live Runtime。

### 3. Adapter Generator 改为安全默认与原子生成

- 默认只输出 Diff/Plan；实际写入必须使用显式 `--write`，`--check` 继续只读。
- 写入前验证 Profile 必填字段、未知字段、目标路径、类型与原生结构；输出目录中的 symlink/特殊文件必须拒绝。
- 所有输出先写 Staging、校验后再整体替换；任一失败必须回滚，不能留下部分更新。
- Generator 版本升级并由测试固定；Generated Manifest/Output 与 Source 的绑定由固定 Commit 和 Pack Evidence证明。

### 4. Generated Adapter 与已部署目标必须精确一致

- Repository Validator/Adapter Check 同时验证 Manifest 声明覆盖完整、无多余 Generated 文件、无 symlink/特殊文件，并校验部署目标字节一致。
- 根级 `.codex/config.toml`、`CLAUDE.md`、`.claude/settings.json`、`.gemini/settings.json` 继续标记 Generated，不得直接维护。
- `03_adapters/README.md` 明确 Generated 状态不等于 Approved Rule、Config Load 或 Runtime PASS。

### 5. Deployment Apply 增加授权、不可变记录与全事务回滚

- 只接受受管 `03_adapters/*/manifest.toml`；Manifest、Source、Target 与 Backup 全部执行 realpath containment、symlink 和特殊文件检查。
- Apply 必须接收单次授权引用并记录 Target Scope；项目级与用户级部署不得混用授权。
- 固化 Plan Digest、Source/Previous/Deployed Hash、权限模式、Backup 路径、Applied At、授权引用和 Rollback 状态；记录不得覆盖。
- Backup、Staging、Replace 与 Record Write 任一步失败时全部回滚；不得留下部分部署、部分 Backup 或无记录的成功写入。

### 6. Recovery V0.2 与纯净发行包边界

- V1.2 Recovery Evidence 必须显式声明 `tree_digest_version = "0.2"`，绑定最终冻结 Commit、Bundle 路径/SHA、Bundle Head、Commit Tree 与实际恢复测试。
- Bundle Artifact 继续位于 Git 忽略目录，不伪装成 Canonical Git 内容；纯净发行包与恢复包分开生成和校验。
- Private Remote、全新设备、大型资产和 Secret 重绑定在真实验证前继续为 `NOT_TESTED`，不得因配置了 `origin` 自动视为灾备完成。
- 本 Pack 只批准生成/验证流程，不立即刷新 V1.2 Recovery Evidence；刷新必须等待 Pack 06 与最终实现冻结。

### 7. Promotion 必须按资产性质分层

- Compatibility/Deployment 规则与 Profile 可升级为 Approved Contract。
- Platform/Capability/Runtime Registry 保持时间敏感 Evidence；Generated Adapter 与部署目标保持 `GENERATED/WORKING`。
- 不修改用户级 Agent 配置，不启用 Hook/MCP/Plugin/Skill，不执行 Live Runtime 或外部数据传输。
- 最终固定 Implementation Commit、Tree Digest、Adapter Diff、Deployment Tests 和各平台 Config Check；本 Pack批准不构成 Release。

## 初审结论

整体规则与 V1.1.3 已批准 Router、安全边界和实际 Harness 行为一致，没有发现需要改变目标、权限模型或状态机的架构冲突。建议在完成以下 4 项修正后整包批准。

## 批准前必须修正

1. `CONCURRENCY_POLICY.md` 使用未登记任务状态 `READY_FOR_REVIEW`；应改为 V1.1 Minimum 的正式状态 `REVIEW`。
2. `APPROVAL_POLICY.md` 强制每项批准记录单独保存内容 SHA-256，与当前“固定 Commit + annotated tag + Git Tree”证据模型不完全一致；应允许“内容 Hash 或不可变 Git Tree/Manifest Digest”。
3. `governance/README.md` 仍称当前内容只是骨架；批准后应声明其为正式治理规则入口，同时继续明确不会自动授予 Promotion 权限。
4. `EXTERNAL_DATA_POLICY.md` 仍声明 `Canonical Authority: NONE`；只有 Founder 确认本 Pack 后才能改为 `FOUNDER_APPROVED`。

## Promotion 时的机械变更

- 16 个文件的状态从 `WORKING` 更新为 `APPROVED`。
- `states.toml` 的 `schema_version` 从 `0.3.0-working` 固化为稳定版本，并将 `artifact_state` 更新为 `APPROVED`。
- `gc.toml` 的 `schema_version` 从 `0.1.0-working` 固化为稳定版本，并将 `maturity_state` 更新为 `APPROVED`。
- Markdown 规则统一记录 `Canonical Authority: FOUNDER_APPROVED`；不改变具体安全禁令。
- 产生一个 Decision Record，绑定 Pack 范围、最终 Commit、Founder、日期和适用条件。

## 不随本 Pack 批准的内容

- 不批准 Hook 自动执行、外部数据传输、Secret 访问、Push、Deploy 或破坏性 GC。
- 不批准 Pack 04/05/06 的内容。
- 不批准任何当前业务项目或 Runtime Registry 内容。
- 不构成 V1.2.0 Release Approval。

## 风险与回滚

- 风险：状态批量替换可能误把运行时 Working 记录升级为 Approved；本 Pack 严格限于上述 16 个文件。
- 风险：规则文字与 Harness 行为可能漂移；Promotion 后必须运行 Schema、Repository、Hook、GC 与 Release Audit 测试。
- 回滚：使用独立 Promotion Commit；失败时通过 Git revert 恢复，不移动既有 Release Tag。
